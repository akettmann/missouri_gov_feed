# missouri-gov-feed

A data pipeline that profiles every current Missouri public official: statewide executives, the
General Assembly, the congressional delegation, tracked mayors, and state and federal judges in Missouri.
Python loaders fetch public records; dbt (DuckDB locally) turns them into one profile per official.

```
uv sync
uv run mogov run          # stage-1 loaders -> dbt build -> stage-2 loaders -> dbt build
uv run mogov export       # marts + reporting -> data/exports/*.parquet (--format csv also works); then `pnpm build` in frontend/
```

Or with Docker only: `docker compose up` (see [docs/environment.md](docs/environment.md#local-in-docker-compose)).

If a loader fails, `mogov load` still runs the rest and exits non-zero; `mogov run` stops before `dbt build` unless you pass `--allow-failed-loader <source>` (stale data is warned about by name; exit stays non-zero).

Other commands: `mogov list` (loaders), `mogov freshness`, `mogov load <loader> ...`, `mogov build [dbt args]` (for example `-s +fct_votes`).
`load` and `run` take `--shards N` (every shard) or `--shards N --shard i` (one shard, as in a Cloud Run task), and `--workers N` (processes; loaders of different services run concurrently).

Docs: [building an environment](docs/environment.md) (local and Cloud Run), [keeping it in sync](docs/sync.md),
[sources and their quirks](docs/sources.md), [how donor PACs are put in industries](docs/interest_keywords.md), [Sunshine Law requests](docs/sunshine_requests.md) and a [summary of the law](docs/sunshine_law_summary.md), [dbt practices review](docs/dbt_best_practices.md), and PlantUML diagrams in [docs/diagrams](docs/diagrams) (SVGs regenerated by a pre-commit hook; needs Java).

## What you get (dbt `marts` schema)

| Category requested | Model | Sources |
|---|---|---|
| Officials | `dim_official`, `official_profile` | Open States, MO House XML, congress-legislators, statewide seed, Official Manual, FJC |
| Forced disclosures | `fct_disclosures` | U.S. House Clerk (annual reports and trades), Senate eFD, federal judges' AO-10 reports (CourtListener) |
| Voluntary disclosures | `fct_voluntary_disclosures` | hand-curated `dbt/seeds/voluntary_disclosures.csv` (no feed exists) |
| Donations to / from them | `fct_campaign_finance`, `fct_federal_donor_summary`, `fct_lobbyist_gifts`; committee spending and report totals in `fct_campaign_spending`, `fct_campaign_reports` | FEC bulk + API; MEC via the Accountability Project mirror (2011–2022); MEC direct (opt-in) |
| Biases | `fct_bias_indicators` | DW-NOMINATE, Shor-McCarty, party-unity computed from votes |
| Family in company leadership | `fct_family_ties` | Wikidata relatives and the organizations they lead; spouse/dependent items on disclosures |
| Districts (find my officials) | `dim_district`, `fct_official_districts` | Census TIGER/Line boundaries; Official Manual county→circuit table; `mo_county_courts` seed (appellate and federal districts) |
| Companies operating in their district | `fct_district_facilities`, `fct_jurisdiction_businesses` (flags the ones that gave to the official) | EPA Facility Registry Service (regulated sites only); campaign finance above |
| Salaries | `fct_salaries` | Missouri state payroll (data.mo.gov), 2017+; `federal_salaries` seed (statutory pay for Congress and federal judges) |
| Bills and their subjects | `fct_bills`, `fct_bill_subjects`, `fct_bill_sponsors`, `fct_vote_bills` | MO House bill XML (subjects from 2024); MO Senate topical index (Senate bills, and subjects for earlier House bills that reached the Senate); Senate votes linked through the journal's measure |
| Voting history | `fct_votes` | MO House roll-call PDFs, MO Senate journals (last 10 years by default), Voteview (Congress) |
| Past offices | `fct_office_history` | Open States, congress-legislators, Wikidata, FJC, CourtListener, Official Manual bios |
| Commercial ventures and relationships | `fct_commercial_ties` | disclosure positions, income, compensation and agreements; Wikidata |
| Case history (judges and lawyers, current or former) | `fct_legal_careers`, `fct_case_history` | bios, Wikidata, FJC; CourtListener bulk dockets/opinions (quarterly) plus API top-ups |

The `reporting` schema reshapes these for the frontend (one model per view, same enforced contracts):

| Model | What |
|---|---|
| `rpt_indicator_peers` | each bias indicator with its chamber peers' median/range and the party medians |
| `rpt_party_breaks` | party-line votes where the official voted against their party's majority |
| `rpt_attendance` | attendance % per official, chamber and session, next to the whole chamber's rate |
| `rpt_donor_rollup` | money received per donor, donor class (PAC, individual, ...) and year |
| `rpt_gift_rollup` | lobbyist gifts per principal, category and year |
| `rpt_interest_vote_overlap` | legislators' votes on bills whose subjects touch an industry that gave them money (co-occurrence, not causation; industries from the `interest_keywords` and `industry_subjects` seeds) |
| `rpt_officeholders_by_year` | who held each tracked office in each year: everyone serving now for the current year; past holders of the MO House (2017+ rosters), MO Senate (years where Open States dates every seat), Congress and federal courts before it |

Party majorities (party unity, party breaks) and chamber attendance count every member who voted, not
only the officials tracked today (`int_votes__member_votes`).

`official_profile` has a `*_status` column per category: `available`, `none found`, `not applicable`, or
`not public` (with how to obtain it), so gaps are explicit rather than silent.

Name-matched records carry a `match_confidence` column. Read medium-confidence matches with care.

## Configuration (`.env`, gitignored)

| Variable | Effect |
|---|---|
| `FEC_API_KEY` | api.data.gov key. Adds donor aggregates and leadership-PAC lookups (DEMO_KEY is ~10 calls/hour). |
| `MOGOV_CONTACT` | Email or URL put in the User-Agent. Required by Wikidata; enables the `wikidata` loader. |
| `MOGOV_ACCEPT_SENATE_EFD_TERMS=1` | Accept the Senate eFD use statement; enables `senate_efd`. |
| `COURTLISTENER_TOKEN` | Free courtlistener.com token. Adds case outcomes and lifts the 5 requests/minute limit. |
| `MOGOV_CL_MAX_QUERIES`, `MOGOV_CL_PAUSE` | Case-search cap and pacing. Without a token the defaults are 60 searches per run, 15 s apart; results are cached for 30 days, so repeated runs make progress. |
| `MOGOV_MEC_OPT_IN=1`, `MOGOV_MEC_USER_AGENT` | Enables direct MEC campaign-finance and lobbying exports (2023+). MEC's robots.txt disallows these pages and its bot protection rejects non-browser clients; see `src/mogov/loaders/mec.py`. |
| `MOGOV_LOG_JSON=1`, `MOGOV_LOG_LEVEL` | structlog output as JSON lines / log level (default INFO). |
| `OTEL_EXPORTER_OTLP_ENDPOINT`, `MOGOV_METRICS_CONSOLE=1` | Export OpenTelemetry metrics over OTLP, or print them: `mogov.loader.rows`, `.duration`, `.failures`, `.progress` (by loader and shard), `mogov.http.requests`, `.bytes`, `.duration` (by host). |
| `MOGOV_FEC_INDIV=1` | Also land FEC individual contributions (~2.3 GB per cycle). |
| `MOGOV_LOOKBACK_YEARS` | Years of state roll calls, House and Senate (default 10, ending this year; House PDFs go back to 2014). |
| `MOGOV_MEC_*_YEARS`, `MOGOV_FEC_CYCLES`, `MOGOV_VOTEVIEW_CONGRESSES`, ... | Other coverage windows (see each loader's header). |
| `MOGOV_PROGRESS_SECONDS` | How often loaders log `loader.progress` (default 15). |
| `MOGOV_DUCKDB_MEMORY`, `MOGOV_DUCKDB_THREADS` | DuckDB limits per landing process (default 3GB, 4); lower them when running many shards. |

## Layout

```
src/mogov/loaders/   one module per source; lands raw data only (data/raw/<table>/part-<shard>-of-<shards>.parquet)
src/mogov/http.py    cached, polite HTTP (data/cache/)
dbt/models/staging/<system>/  one source per system (_<system>__sources.yml); one model per raw table: typing and renaming
dbt/models/intermediate  identity resolution (vote tokens -> people, committees -> officials, ...)
dbt/models/marts     the per-official facts above
dbt/macros/compat    adapter.dispatch macros (JSON, regex, dates, casts) so models are backend-portable
```

Rules for contributors:

- Python only extracts and lands data; every transformation is dbt.
- dbt SQL must stay portable. Use `mogov.*` and `dbt.*` macros, not DuckDB-only syntax.
- The marts have enforced contracts: changing a mart column means updating its `data_type` in
  `dbt/models/marts/_marts.yml`. Name-matching logic has dbt unit tests (`_*__unit_tests.yml`); extend
  them when you change a matching rule.
- Model docs: mart columns are hand-written in `dbt/models/marts/_marts.yml` (shared definitions in
  `dbt/models/_docs.md`) and land as DuckDB table/column comments. Staging and intermediate descriptions come
  from each model's SQL header comment, so edit the header and run `uv run python scripts/gen_model_docs.py`.
- pre-commit runs ruff, sqlfluff and the PlantUML renderer (`uv run pre-commit install`). Edit the `.puml`; the hook writes the `.svg` (stamped with the source's hash, which CI checks), so stage it and commit again.

## Known gaps (data not obtainable online)

- **Missouri personal financial disclosure statements** (legislators, statewide officers, judges) are released only on written Sunshine Law (RSMo 610) request: from MEC for officials, from the Clerk of the Supreme Court for judges.
- **MEC campaign finance after 2022** requires the opt-in `mec` loader.
- **MO Secretary of State business registry** (company officers) sits behind bot protection with no bulk export. Family and business ties therefore come from Wikidata and disclosures only.
- **Case.net** (state trial courts) prohibits automated access under Court Operating Rule 2.02. Case history covers appellate and federal opinions in CourtListener; its Missouri state opinions end in 2025.
- **State roll calls** cover the last `MOGOV_LOOKBACK_YEARS` (default 10). House roll-call PDFs start in 2014.
